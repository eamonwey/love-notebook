# 解绑与重新绑定

- 解绑事务封存共同配对、终止活动周期并清空双方当前绑定。中断期不补交换，不公开尚未交换的分数、笔记和事件。
- 重新生成邀请，由原伴侣接受后恢复最近一本属于这两个微信账号的封存笔记本。换其他人绑定时创建全新的共同记录，不能访问前伴侣记录。
- 恢复后沿用旧配对的周期天数和钻石额度，并从恢复时刻开始新一期；期数接续，中断期占一期但没有分数。旧的已交换记录、批注、事件与礼物仍关联原配对。
- 追踪图将中断期显示为“暂停”，不把前后的分数相连，并显示解绑和恢复时间。多次解绑保留多个断点。横轴仍然按期数排列，不是按自然日等比例排列。
- 旧版解绑没有记录准确时间时，显示“解绑时间未记录”，不编造日期。若历史已有多本同伴侣笔记本，仅恢复最近的一本，不自动合并。
- 本地演示模式原本不支持绑定/解绑；此流程需在云开发双账号测试。

## 部署与验收

部署 `pair`、`track` 云函数，更新小程序。无需新集合；查询涉及 `pairs(status, users, createdAt)` 与 `cycles(pairId, status, index)`，按云数据库提示补充相应索引。

双账号依次验证：已交换一期 → 新一期尚未交换时解绑 → 定时任务不交换中断期 → 新邀请确认恢复 → 旧记录可查看、新一期无旧分数 → 新一期交换后曲线在暂停处断开。再验证绑定第三人时不能查看原配对记录。
