# 代码审查修复部署说明

本轮修复：解绑与建周期竞争、旧笔记批注提醒遗漏、历史页重试方向、并发已读位置回退、并发笔记数量超限、三个接口返回内部作者标识。

## 部署

1. 在数据库核对普通非唯一索引 `notes(pairId 升序, author 升序, _id 升序)`，已有等价索引不用重复创建。
2. 在低使用量时段完整上传部署 `cycle`、`note`、`pair`、`track`、`reminder`。三个建周期入口新增了各自的 `cycle-store.js`，不能只上传 index.js。全部更新后再验收，混用旧版函数不具备完整并发保护。
3. 重新编译、预览小程序，发布时一并更新前端。

不需要新集合或批量迁移。`cycleRevision`、`noteCount`、`noteRevision` 随业务操作自动写入；旧周期首次新增笔记会初始化名额计数。本轮不自动删除或合并已存在的异常历史周期。

## 验证边界

本地 `npm test` 覆盖模拟数据库和页面回归；模拟事务串行执行，不能替代真实云数据库的冲突重试测试。部署后双机验证：换期时解绑、99条笔记时同时新增、旧笔记新增批注、双设备同时标记已读，以及断网后历史页重试。

批注提醒暂以完整分页扫描保证正确性，记录很多时读取成本会增长；后续可迁移为独立回复收件箱，但不要恢复为仅扫描最新100条笔记。
