# 启动性能与部署

本次仅修改本地代码，尚未部署云函数或在远端创建索引。

## 部署顺序

1. 新环境一次性创建 users、pairs、cycles、notes、events、gifts 集合；已有环境升级礼物功能需补建 gifts，见 [礼物部署说明](gifts.md)。集合权限保持仅服务端访问，勿因优化开放客户端读写。
2. 先上传并部署 cycle、pair、login 云函数，再编译/发布小程序。前端依赖 cycle.getExchangePage 新接口，不能只更新前端。
3. 在云开发数据库控制台按下表建立普通（非唯一）索引，已有等价索引无需重复创建。确认索引构建完成。
4. 开发者工具网络面板对比首次启动、再次进入首页、交换页、设置页的调用次数和耗时；云端部署版本必须与本地一致。

## 索引清单（按顺序添加字段）

| 集合 | 字段与排序 | 用途 |
| --- | --- | --- |
| users | openid 升序 | 身份和昵称 |
| cycles | pairId 升序、status 升序、index 降序 | 活动周期、最近交换、计数 |
| cycles | pairId 升序、index 降序 | 创建下一期时查询最大期数 |
| notes | cycleId 升序、createdAt 降序 | 已交换详情 |
| notes | cycleId 升序、author 升序、createdAt 降序 | 未交换详情，仅本人可见 |
| notes | pairId 升序、author 升序、_id 升序 | 批注提醒完整游标扫描，避免遗漏旧笔记的新批注 |
| pairs | code 升序、status 升序 | 邀请查询 |

不直接创建 openid 唯一索引：必须先检查历史重复用户数据。这里只增加查询索引，不做数据清理。

## 已优化的请求

- 冷启动：wx.cloud.init 仅做本地 SDK 初始化，首屏直接调用 cycle.getCurrent，省去 login 以及每次五次建集合操作。
- 普通已绑定首页：六次数据库读取；当前用户资料复用，昵称与周期并行，最近周期与计数并行。历史查询等待自动交换完成，保证一致性。
- 等待绑定：首页仅读取用户和配对两次，返回 cycle:null，不查询历史。
- 交换页：一次 cycle.getExchangePage 调用，普通有详情时八次数据库读取；身份、配对、昵称在同次请求内复用，仍校验周期归属和交换前可见性。
- 设置页：一次 pair.get，不再加载周期和交换历史。
- 首页/交换页：15 秒轮询，请求未结束时复用 Promise；隐藏后停止轮询并忽略成功响应。首页铃铛保持独立的 20 秒刷新及独立请求锁，状态先渲染后读取回复，回复请求不属于首屏关键链路。
- 不缓存云端业务响应，也没有跨用户共享服务端上下文。编辑中的笔记草稿会暂存在当前设备，保存成功即清除，最长保留 7 天。

## 耗时字段

cycle.getCurrent 的 result.data.timings 包含 userMs、pairMs、usersMs、cycleMs、historyMs、totalMs；getExchangePage 另有 detailMs，外层 totalMs 包含详情。计时单位为毫秒。并行阶段不能直接相加；totalMs 不含网络和平台冷启动。可通过开发者工具查看云函数响应，结合完整网络耗时判断瓶颈。

## 验证

运行 `npm test`。新增断言覆盖一次首屏云调用、一次交换页调用、未绑定两次读取、正常首页六次读取、合并详情八次读取、跨配对拒绝、交换前隐私，以及轮询请求锁和隐藏生命周期。

本地桩可验证请求次数和权限行为，但不能代表真实网络、冷启动或索引性能。部署后再测实际秒数，不承诺固定提速百分比。

六个云函数均固定使用 `wx-server-sdk 4.0.2` 并提交各自的 `package-lock.json`，避免不同时间部署时解析出不同依赖树。升级后仍应在真实云环境验证数据库事务和内容安全云调用。
