# 恋恋温度计 · Love Notebook

基于微信小程序与微信云开发的双人感情记录工具。双方使用各自的微信账号邀请绑定，在周期内打分、记录心情，交换后查看彼此的分数和笔记，并通过批注、礼物和趋势图回顾相处过程。

## 功能

- **伴侣邀请**：微信分享卡片或邀请码绑定，同一账号同时只能绑定一位伴侣。
- **周期打分**：0–10 分及留言，交换前可以改分；对方分数、留言和笔记由服务端隔离。
- **交换记录**：双方打分后可发起、同意提前交换；周期到期且双方已打分时自动交换。
- **心情笔记与批注**：记录开心或不满，交换后互相批注，可删除自己的内容；首页铃铛提示未读回复。
- **分数追踪**：分页浏览折线图、记录变化事件、横屏全屏展示，导出完整分数历史为图片。
- **免费虚拟礼物**：小红花、情书、跑车及收礼动画；每人每期免费钻石额度可共同设置为 0–100 的整数。
- **解绑与恢复**：解绑封存共同记录，重新绑定同一伴侣恢复历史，趋势图保留中断位置。
- **本地演示**：无需云环境，切换“小A / 小B”体验双人流程。

钻石不支持充值、提现或兑换现金。目前不发送微信订阅消息，也不提供约定提醒时间功能。

## 环境要求

- 微信开发者工具，以及自己有权限管理的小程序 AppID。
- 已开通的微信云开发环境。
- 本地 Node.js，用于运行测试；GitHub 自动测试使用 Node.js 22。
- 云函数各自管理依赖，当前固定使用 `wx-server-sdk@4.0.2`，各目录保留依赖锁文件。

## 快速开始

### 1. 获取代码

```bash
git clone https://github.com/eamonwey/love-notebook.git
cd love-notebook
```

私有仓库需要对应访问权限。

### 2. 配置微信项目

在微信开发者工具导入仓库根目录，读取 `project.config.json`。前端目录为 `miniprogram/`，云函数目录为 `cloudfunctions/`。

使用自己的小程序时，将 `project.config.json` 的 `appid` 替换为自己的 AppID，并在 `miniprogram/config/index.js` 填写云环境：

```js
module.exports = {
  useMock: false,
  cloudEnvId: '你的云开发环境ID',
};
```

仓库中的 AppID 和环境 ID 是原项目配置，不是 AppSecret，也不授予云环境访问权限。不要将 AppSecret、GitHub Token 或云服务密钥写进源码。

### 3. 创建数据库与索引

在所选云环境中创建以下集合：

```text
users  pairs  cycles  notes  events  gifts
```

业务集合仅允许服务端读写，由云函数校验身份、配对关系和内容可见性。不要开放客户端直接访问情侣记录。

索引按 [启动与索引说明](docs/startup-performance.md)、[礼物部署说明](docs/gifts.md) 和 [审查修复说明](docs/review-fixes.md) 配置。

### 4. 部署云函数

分别右键六个云函数目录，选择“上传并部署：云端安装依赖”：

```text
login  pair  cycle  note  track  reminder
```

上传完整目录，包括 `config.json`、辅助 JS 文件和依赖锁文件。云函数独立部署，`cycle-calendar.js`、`cycle-store.js` 的对应副本必须保持一致。

确认云端 `reminder` 的 `exchangePlanReminder` 定时触发器已启用，Cron 为：

```text
0 * * * * * *
```

即每分钟检查到期周期。函数代码和触发器配置更新需分别核对，实际调度可能有延迟。完整说明见 [自然日周期](docs/early-exchange.md)。

### 5. 双账号体验

两台手机使用不同微信账号，一方选择周期并分享邀请，另一方接受后验证打分、交换、批注、收礼和图表。使用体验版时，将测试账号加入小程序体验成员。

上线前需在真实云环境验证内容安全接口、数据库事务、相册授权及手机适配。

## 本地演示

将 `miniprogram/config/index.js` 中的 `useMock` 改为 `true`，在设置页切换“小A / 小B”。数据保存在本机缓存，支持重置。正式发布应恢复为 `false`。

## 业务规则

- **自然日周期**：以北京时间零点为分界，开始当天算第 1 天。一天一期在 10 月 7 日 20 点开始，10 月 8 日零点到期；七天一期在 10 月 14 日零点到期。
- **自动交换**：到期且双方已打分则自动交换；缺少一方分数则等待补齐。首页、提交分数和定时任务都会检查。
- **提前交换**：双方打分后，一方发起、另一方同意。本期立即交换，下一期次日零点开放；等待期间可以补笔记、写批注和使用本期钻石，分数冻结。
- **设置**：周期天数与钻石额度的修改从下一期生效。每人的余额独立、不累加，新期按共同设置重置。
- **笔记额度**：每期双方合计最多保留 100 条笔记，删除本期笔记释放名额；没有总历史 100 条限制，批注不计入额度。
- **删除与可见性**：交换前对方内容不下发，交换后共同查看。只能删除自己的笔记、批注和事件，删除笔记会删除附属批注。
- **解绑**：封存历史并中断本期。同伴侣重新绑定恢复历史，换伴侣建立独立笔记本；解绑不等于删除数据。
- **内容安全**：昵称、笔记、批注、打分留言和事件原因通过微信文本安全检测。本地草稿保存后清除，最长保留 7 天。

## 测试

在仓库根目录运行：

```bash
npm test
```

根目录测试使用 Node.js 内置模块，无需安装根目录依赖，不访问真实云数据库。覆盖 JSON、语法、模拟业务流程、云函数数据库桩、页面交互、图表边界、启动调用及礼物逻辑。

云函数线上运行仍需各自依赖。本地安装时进入对应目录执行 `npm ci`，不要提交 `node_modules/`。

GitHub 在推送和拉取请求时自动运行测试。离线测试不替代双机验收和真实云数据库并发测试。

## 发布注意事项

正式上线前确认云端代码与仓库一致，完成双账号真机验收，填写实际的信息处理用途和隐私保护指引，并确认小程序备案与服务类目。

项目存储账号标识、昵称、伴侣关系和用户记录；保存导出图片涉及相册写入权限。当前尚未提供完整账号注销或历史数据删除申请流程。运维时配置访问权限、备份、错误告警和费用提醒。

`project.private.config.json`、凭据、依赖目录及临时备份不纳入仓库。功能先在测试环境验证，再部署到正式环境。
