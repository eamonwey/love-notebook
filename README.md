# 恋恋温度计（love_notebook）

一个微信小程序：两个人在周期内各自给这段感情打分（0-10），周期结束交换后才能看到对方的分数、留言和感受笔记，并可互相批注；持续追踪分数变化及背后的原因。

**真实双人、两台手机**：基于微信云开发，一方通过微信把邀请卡片发给另一方，对方点开即完成绑定；此后两个人在各自手机上用各自的微信登录操作，服务端按 openid 隔离数据。

## 功能与实现对应

| 需求 | 实现 |
| --- | --- |
| 1. 周期内双方打分 0-10，交换后互相可见；一方未打分不能交换 | 云函数 `cycle` 周期模型 + `pages/score` 打分页 + `pages/exchange` 交换中心（服务端校验交换门槛） |
| 2. 随时记录开心/不满的感受；交换后双方可见并可批注 | `pages/notes` + `pages/note-edit` + 交换详情页内的批注（云函数 `note`） |
| 3. 自定义交换周期（如 7 天一期），打分仅限当前周期 | `pages/settings` 周期设置（下一期生效）；打分/记录只写入当前 active 周期，交换后冻结 |
| 4. 在分数变化节点记录事件 | 打分时自动与上期比较，变化即弹出原因记录；`pages/history` 分数曲线 + 事件时间线，支持手动补充 |
| 5. 微信邀请另一半，两台手机各自使用 | `pages/pair` 生成邀请码 → **微信分享卡片** → 对方点开一键接受绑定；也支持手动输入邀请码 |
| 6. 自由选择交换时机 | 交换统一走「**一方发起请求 → 对方同意**」流程，没有直接交换入口；还可用**滚筒选择器约定交换时间**（第几天 × 几点，天数列随周期长度变化） |
| 7. 微信通知提醒 | 接入**订阅消息**：对方发起交换请求时提醒你；约定时间到点由 `reminder` 定时云函数同时提醒双方，防止忘记打分交换 |

## 快速开始（真实双人，需一次性配置云开发）

1. 微信开发者工具打开 `E:\love_notebook`（appid 已配置）。首次运行若提示需要配置，会自动进入「配置引导」页。
2. 开发者工具顶部点「**云开发**」→ 开通并创建环境 → 复制**环境 ID**，粘贴到 `miniprogram/config/index.js` 的 `cloudEnvId`。
3. 在 `cloudfunctions` 目录中，对 `login`、`pair`、`cycle`、`note`、`track`、`reminder` 六个云函数分别**右键 → 上传并部署：云端安装依赖**（部署 `reminder` 时会自动创建每小时整点的定时触发器）。
4. 编译运行。数据库集合会在首次调用时自动创建。
5. 绑定另一半：首页 →「去邀请TA」→ 设置昵称 → 生成邀请码 → **「通过微信邀请TA」**分享卡片 → 对方在自己手机上点开卡片 → 「接受邀请」即完成绑定。

## 开启微信提醒（订阅消息，可选）

小程序的通知走「订阅消息」（显示在微信的「服务通知」里），需要一次性配置：

1. mp 后台 → 功能 → 订阅消息 → **公共模板库** → 选一个字段为「**事项（Thing）/ 时间（Time）/ 备注（Thing）**」的提醒类模板（如「打卡提醒」「日程提醒」），添加后复制**模板 ID**。
2. 把模板 ID 填到三处：
   - `miniprogram/config/index.js` → `subscribeTemplateId`
   - `cloudfunctions/cycle/index.js` → 顶部 `TEMPLATE_ID`
   - `cloudfunctions/reminder/index.js` → 顶部 `TEMPLATE_ID`
3. 若所选模板的字段编号不同（如 `thing4/time5`），同步修改两处云函数里的 `FIELDS`。
4. 重新上传 `cycle` 和 `reminder` 两个云函数，重新上传体验版。
5. **体验版测试时**，把两个云函数里的 `NOTIFY_STATE` 改为 `'trial'`（正式发布后改回 `'formal'`），否则点开通知会跳转失败。

提醒机制说明：订阅消息是**一次性授权**——用户每点一次「允许」只能收到一条。小程序会在**打分保存、发起交换请求、约定交换时间**这几个动作时顺势请求授权；多点几次「允许」就能多收几条提醒。对方发起交换请求时你会立即收到提醒；约定的交换时间到点（每小时整点检查），双方各收到一条提醒。

## 两台手机上测试

- **真机预览**：开发者工具点「预览」生成二维码，两台手机分别扫码登录各自的微信。其中一台发起微信邀请，另一台点开聊天里的卡片完成绑定，之后各自操作即可。
- 联调数据都在云端，两台手机看到的是同一份周期、彼此隔离的输入，交换前互相不可见（服务端控制）。
- 偶尔需要清掉自己名下的绑定重新测试：云开发控制台删除 `users` 里对应记录（并把 `pairs` 里相应 pair 删除）即可。

## 本地演示模式（开发者调试用，默认关闭）

`miniprogram/config/index.js` 中把 `useMock` 改为 `true`，可以在没有云环境的情况下跑 UI 和完整业务流：内置「小A ⇄ 小B」双账号切换（仅用于一台手机调试界面与逻辑，不是真实使用方式）。设置页可重置演示数据。

## 业务规则（当前实现的设计决策）

- **交换门槛**：交换没有"直接交换"入口——必须**一方发起交换请求、对方同意**后才执行；同意时校验双方本期均已打分（云函数侧同样校验）。请求可由任一方撤回；双方都打完分时，发起方页面会提示"TA同意后即可交换"。（到期自动交换是这条规则唯一的系统例外，见下）
- **约定时间**：选「第几天 + 几点」（天数列长度 = 周期天数），按周期开始当天的本地日历日推算钟点（云函数环境为东八区）；只能约定未来的时间，到点只发提醒、不自动交换。
- **到期自动交换**：周期到期时（定时任务每小时判定，打开小程序或补打分时也会即时判定），若双方已完成打分，系统直接自动交换并通知双方，下一期从到期时刻无缝开始、节奏不受影响；若有任一方未打分，则等双方补齐打分后立即自动交换，下一期从补齐那一刻起算（节奏相应顺延）。这是系统行为，无需发起请求。
- **可见性**：交换前只能看到「对方是否已完成打分」的对勾，看不到分数/留言/笔记；交换后服务端才返回对方数据（云函数 `cycle.getDetail` 侧过滤，不只是前端隐藏）。分数变化事件遵循同一规则：进行中周期的事件仅本人可见，交换后双方可见。
- **提前交换**：允许在周期未结束时提前交换（只要双方都已打分）；周期到点未交换会持续提示，仍可补打分后交换（否则该期会无法收尾）。
- **打分范围**：只能在当前 active 周期打分/记录；交换后该期数据冻结（不可再打分、不可删笔记），只能追加批注。
- **周期长度**：修改后下一期生效，不影响进行中的一期。
- **分数事件**：打分时与你自己上一期（已交换周期）的分数比较，变化时提示填写原因；也可在追踪页手动补记。追踪页长按可删除**自己添加**的事件。
- **内容安全**：昵称（场景：资料）、笔记、批注、打分留言、事件原因（场景：社交日志）在保存前统一过微信 `msgSecCheck` 2.0 检测；判定违规的内容拒绝保存并提示修改，笔记会保留本地草稿不丢失；安全接口自身故障时放行并记日志，不阻断正常使用。
- **绑定关系**：一个邀请码只能用一次（绑定后失效）；一个人同一时间只有一个配对。已生成过邀请但还没人加入的一方，也可以直接输入对方的邀请码——会自动作废自己未完成的邀请再加入对方。等待绑定期间首页每 5 秒自动刷新，绑定成功后无需手动操作。**第一期从双方绑定完成的那一刻开始计时（绑定前不创建周期）**。**解绑**：设置页可单方面解绑，**无需对方同意**；解绑会同时终止进行中的周期（不再通知、不再自动交换），原笔记本封存（历史数据保留在数据库但不再展示），双方都可以重新邀请绑定新的伴侣，从第 1 期重新开始。
- **并发与一致性**：接受邀请、打分写入、周期状态翻转均使用**条件更新（原子 compare-and-set）**，并发下不会出现三人配对、重复交换或向已交换周期写入；周期文档使用确定性 ID（`cyc_<pairId>_<期数>`）；若历史数据中存在重复的进行中周期，`cycle` 云函数会在加载时自动合并双方打分并清理多余文档（自愈）。云函数间的公共辅助函数为各自独立副本，便于单独部署，后续可抽公共包。

## 常见问题

- **首页提示「先接入微信云开发」？** 尚未配置 `cloudEnvId` 或云函数未部署，点按钮进入配置引导，按步骤完成后点「重试」。
- **提示「还没有和TA配对」？** 首页点「去邀请TA」，微信发卡片给对方绑定。
- **对方点卡片提示「邀请已失效」？** 邀请码已被使用或已过期，重新生成一个再分享。
- **想改回本地调试？** `config/index.js` 中 `useMock: true`。
